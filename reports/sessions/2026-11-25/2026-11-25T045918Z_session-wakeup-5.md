## New source-semantic finding

The updated Treasury auctions v2 endpoint returned 64 rows in one complete page, with record-date coverage 2026-10-01 through 2026-11-24. It contains one 10-year Note sample for auction date 2026-11-10, CUSIP `91282CRX1`, record date 2026-11-16.

The persisted API row and official result XML show:

- Primary-dealer competitive award: $4,080,513,500.
- Direct competitive award: $12,109,950,200.
- Indirect competitive award: $25,566,955,000.
- Competitive awards inside the offering amount: $41,757,418,700; outside: $0.
- The three bidder-class awards sum exactly to the competitive-award denominator. The implied primary-dealer share is **9.7719%**.
- The distinct recognized amounts are much larger: primary-dealer competitive recognized $57,556,000,000 and competitive recognized inside the offering $103,060,038,000. They must not be substituted for awarded/accepted amounts in the share feature.

The first automated crosswalk in run 455491 stopped at a representation difference, not an amount discrepancy: the API reports `inflation_protected=No`, while the XML reports `InflationProtected=N` (the same convention applies to `FloatingRate` and `Reopening`). Direct inspection of the persisted values showed exact API/XML equality for the award and recognized amount fields, but the automated routine had returned before checking them.

I implemented semantic boolean normalization for Yes/No, Y/N, true/false and 1/0, expanded the field selection to include recognized subtotals, and added regression coverage. The full automated 21-field crosswalk now compares metadata, award values and recognized values, then checks that primary + direct + indirect awards equal competitive awards inside + outside. It returns `RECONCILED_SAMPLE_ONLY` on success; it does not admit the row into the model.
